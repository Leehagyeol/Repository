# 저장소 웹앱 기획문서

2026-11-24

## 개요

아이폰 Safari에서 홈 화면에 추가해 쓰는 개인용 저장소 웹앱이다. 나중에 다시 보고 싶은 영상, 웹페이지, 사진, 메모를 한곳에 모으고 6개 카테고리로 나눠 찾는다.

- **사용자**: 본인 1명. 로그인과 공유 기능은 두지 않는다.
- **핵심 가치**: 링크를 붙여넣으면 제목과 미리보기 이미지가 자동으로 붙어서, 목록만 훑어도 무엇인지 알 수 있다.
- **기억 보조**: 링크와 사진에는 키워드를 함께 달아, 제목이 기억나지 않아도 키워드로 찾는다.
- **입력 속도**: 다른 앱(YouTube, 인스타그램, 사진 앱)에서 공유 버튼으로 바로 보낼 수 있어야 실제로 쓰게 된다.

앱 이름은 "저장소"이고, 홈 화면 아이콘은 서랍 모양이다.

### 이름·아이콘·색

대표색은 짙은 청록, 서랍은 따뜻한 미색으로 한다. 장보기 앱과 홈 화면에서 나란히 놓여도 구분되도록 차분한 색을 골랐다.

| 항목 | 정한 것 |
| --- | --- |
| 앱 이름 | 저장소 (홈 화면 아이콘 아래 이름도 같음) |
| 아이콘 | 청록 바탕에 미색 3단 서랍. 가운데 서랍이 살짝 열려 있고 손잡이는 노랑 |
| 대표색 | 짙은 청록 `#2F6F68` — 아이콘 바탕, 상단 제목, + 버튼, 선택 표시, manifest의 `theme_color` |
| 바탕색 | 미색 `#F6F1E7` — 아이콘 속 서랍, 앱 배경 |
| 강조색 | 노랑 `#E9B44C` — 서랍 손잡이, 고정(핀) 표시. 글자에는 쓰지 않는다 |
| 다크 모드 | 아이폰 설정을 따라 배경만 어둡게(`#1C2321`), 대표색은 그대로 |
| 아이콘 파일 | `apple-touch-icon` 180×180 PNG(홈 화면용), manifest용 192×192·512×512 PNG |

대표색 위 흰 글자는 명암비가 약 5.8:1이라 작은 글씨도 잘 읽힌다.

## 사용 환경과 기술 방향

장보기 앱과 같은 방식으로, Windows PC의 VS Code에서 Claude Code로 만들고 아이폰 Safari에서 "홈 화면에 추가"해 앱처럼 쓴다. 서버 없이 폰 안에 데이터를 저장하고, 링크 미리보기만 작은 무료 서버 함수에 맡긴다.

| 구분 | 선택 | 이유 |
| --- | --- | --- |
| 개발 | Windows + VS Code + Claude Code | 기존 환경 그대로 |
| 화면 | HTML + CSS + JavaScript (빌드 도구 없음) | 파일 몇 개로 끝나고 수정이 쉽다 |
| 앱처럼 쓰기 | manifest.json + 서비스 워커, `display: standalone` | 홈 화면 아이콘, 주소창 없는 전체 화면, 오프라인 열람 |
| 호스팅 | GitHub Pages | 리포지토리 `Leehagyeol/Repository`의 `storage/` 폴더. 주소는 `https://leehagyeol.github.io/Repository/storage/`. 무료 HTTPS |
| 데이터 저장 | IndexedDB (폰 안) | 사진 파일(Blob)을 그대로 담을 수 있고 용량이 넉넉하다. localStorage는 사진에 부적합 |
| 링크 미리보기 | Cloudflare Workers 무료 요금제의 작은 함수 1개 | 브라우저는 다른 사이트의 HTML을 직접 읽지 못한다(CORS). 기술 제약 참고 |
| 백업 | JSON 파일 내보내기/가져오기 (파일 앱·iCloud Drive로 저장) | 폰 분실·초기화 대비 |

로그인과 클라우드 동기화는 1차 범위에서 뺀다. PC에서도 보고 싶어지면 나중에 Supabase 같은 무료 DB를 붙이는 방향으로 확장한다.

장보기 앱과 같은 GitHub 계정 주소(`leehagyeol.github.io`)를 쓰면 리포지토리가 달라도 브라우저는 두 앱을 같은 사이트로 본다. 그래서 서로의 데이터를 덮어쓰지 않도록 세 가지를 폴더별로 나눈다.

- IndexedDB 데이터베이스 이름과 localStorage 키에 앱 이름을 붙인다 (예: `storage-db`).
- 서비스 워커는 이 앱 폴더 안에 두어 장보기 앱 페이지를 건드리지 않게 한다.
- manifest의 `start_url`과 `scope`를 이 앱 폴더로 지정해 홈 화면 아이콘이 각각 자기 앱을 열게 한다.

## 카테고리 구조와 고르는 방식

가로로 넘기는 탭 대신, 홈 화면에 카테고리 6개를 타일로 보여주는 C안으로 확정했다. 카테고리 안에서는 제목을 눌러 다른 카테고리로 바로 옮긴다. 아이폰 하단 탭 바는 보통 5칸이 한계라 7개에는 맞지 않는다.

검토한 세 가지 방식:

| 방식 | 모양 | 장점 | 단점 |
| --- | --- | --- | --- |
| A. 두 줄 칩 | 목록 위에 칩 4개 + 3개, 두 줄 | 한 번 탭으로 전환 | 목록 위 두 줄을 늘 차지 |
| B. 제목 메뉴 | "레시피 ▾"를 누르면 7개 목록이 펼쳐짐 | 목록이 가장 넓다 | 전환에 두 번 탭, 카테고리가 바로 안 보임 |
| **C. 카테고리 홈 (확정)** | 홈에 카테고리 타일 6개(2열×3줄) + 최근 저장 목록 | 6개가 한눈에 보인다 | 카테고리 안에서는 B 방식으로 전환 |

A는 가장 단순하지만 목록 위 두 줄을 늘 차지한다. B는 목록이 넓지만 어떤 카테고리가 있는지 매번 메뉴를 열어야 보인다. C는 홈에서 한눈에 고르고, 카테고리 안에서는 B의 메뉴로 옮겨 다닌다. [전체] 탭은 홈의 "최근 저장" 목록과 검색이 대신한다.

| 위치 | 주로 담길 것 | 목록 모양 |
| --- | --- | --- |
| 홈 · 최근 저장 | 모든 카테고리의 최근 항목 | 목록 |
| 레시피 | 요리 영상, 레시피 블로그, 요리 사진 | 카드(썸네일 크게) |
| 육아 | 육아 정보 페이지, 놀이 아이디어 영상, 메모 | 목록 |
| 만들기 | DIY·공예 영상, 도안 사진 | 카드(썸네일 크게) |
| 쇼핑 | 상품 페이지 링크, 상품 캡처 | 목록 |
| 메모 | 직접 입력한 텍스트 | 목록(본문 2줄 미리보기) |
| 짤방 | 웃긴 사진, 밈 이미지 | 사진 격자(3열) |

- **홈**: 검색창 → 카테고리 타일 6개(2열 × 3줄, 타일마다 이름·항목 수·최근 썸네일) → 최근 저장 목록. 홈에서 검색하면 전체에서 찾는다.
- **카테고리 화면**: 제목 "레시피 ▾"를 누르면 메뉴가 펼쳐져 다른 카테고리로 바로 간다. 왼쪽 위 ‹ 버튼이나 화면 왼쪽 끝에서 밀어서 홈으로 돌아간다.
- 카테고리는 항목마다 하나만 고른다. 여러 곳에 걸치는 것은 키워드로 보완한다.
- 카테고리 목록은 코드의 설정 한 곳에 모아 두어 이름을 바꾸거나 추가하기 쉽게 한다. 카테고리가 늘면 타일이 한 줄씩 늘어난다.
- 앱을 다시 열면 마지막에 보던 화면(홈 또는 그 카테고리)에서 시작한다.

## 항목 유형과 데이터 모델

항목은 링크·사진·텍스트 3가지 유형이고, 모두 같은 표 하나(IndexedDB의 `items`)에 저장한다. 키워드는 링크·사진에서 입력을 권하고, 텍스트에서는 선택이다.

| 유형 | 사용자가 넣는 것 | 앱이 채우는 것 | 목록에 보이는 모습 |
| --- | --- | --- | --- |
| 링크(영상) | URL, 카테고리, 키워드, 메모(선택) | 영상 제목, 채널명, 썸네일, 사이트 이름 | 썸네일 + ▶ 표시 + 제목 |
| 링크(웹페이지) | URL, 카테고리, 키워드, 메모(선택) | 페이지 제목, 대표 이미지, 설명 한 줄, 사이트 이름 | 대표 이미지 + 제목 + 도메인 |
| 사진 | 사진 1~여러 장, 카테고리, 키워드, 제목·메모(선택) | 줄인 원본, 썸네일 | 썸네일 + 제목 또는 키워드 |
| 텍스트 | 제목(선택), 본문, 카테고리, 키워드(선택) | 없음 | 제목 + 본문 앞 2줄 |

항목 하나의 필드(초안):

| 필드 | 내용 | 예 |
| --- | --- | --- |
| id | 고유 번호 | `a1b2c3` |
| type | `link` / `photo` / `text` | `link` |
| category | 6개 중 하나 | `레시피` |
| keywords | 키워드 목록 | `["에어프라이어", "닭날개"]` |
| title | 제목 (링크는 자동, 사용자가 고칠 수 있음) | `바삭한 에어프라이어 닭날개` |
| note | 메모 또는 텍스트 본문 | `간장 대신 굴소스` |
| url | 원본 링크 (링크만) | `https://youtu.be/...` |
| linkKind | `video` / `page` (링크만) | `video` |
| siteName | 사이트·채널 이름 | `YouTube · 만개의레시피` |
| previewImage | 미리보기 이미지 (폰에 저장한 사본) | Blob |
| photos | 사진들 (원본 축소본 + 썸네일) | Blob 목록 |
| pinned | 상단 고정 여부 | `false` |
| createdAt / updatedAt | 저장·수정 시각 | `2026-11-24 10:12` |

미리보기 이미지는 주소만 저장하지 않고 폰에 복사본을 둔다. 원본 페이지가 사라져도 목록에서 무엇이었는지 알아볼 수 있다.

## 핵심 기능 명세

1차 출시에는 "필수" 항목만 넣고, "권장"은 쓰면서 추가, "나중"은 필요할 때 검토한다.

| 번호 | 기능 | 내용 | 우선순위 |
| --- | --- | --- | --- |
| F1 | 링크 추가 | + 버튼 → 링크 붙여넣기. 클립보드에 링크가 있으면 "붙여넣기" 버튼을 먼저 보여준다 | 필수 |
| F2 | 미리보기 자동 생성 | 링크를 넣으면 1~3초 안에 제목·썸네일을 가져와 입력 화면에 미리 보여준다. 실패하면 공유 문구나 도메인 이름을 제목으로 쓰고 직접 고칠 수 있다. 스크린샷을 미리보기 이미지로 지정할 수 있다 | 필수 |
| F3 | 사진 추가 | 사진 보관함에서 여러 장 선택 또는 카메라 촬영. 긴 변 1600px JPEG로 줄여 저장 | 필수 |
| F4 | 텍스트 추가 | 제목(선택) + 본문. 줄바꿈과 링크는 그대로 보존 | 필수 |
| F5 | 카테고리 선택 | 입력 화면에 6개 버튼. 기본값은 지금 보고 있던 카테고리(홈이면 직접 선택) | 필수 |
| F6 | 키워드 입력 | 입력 후 엔터·쉼표·띄어쓰기로 칩이 된다. 전에 쓴 키워드를 자동완성으로 추천. 링크·사진은 키워드가 비면 "키워드를 넣으면 찾기 쉽습니다" 안내 | 필수 |
| F7 | 카테고리별 목록 | 최신순. 고정(핀) 항목은 맨 위 | 필수 |
| F8 | 검색 | 제목·키워드·메모·사이트 이름에서 찾는다. 카테고리 화면에서는 그 안에서, 홈에서는 전체에서 검색 | 필수 |
| F9 | 키워드 필터 | 항목의 키워드 칩을 누르면 같은 키워드가 붙은 항목만 본다 | 필수 |
| F10 | 상세 보기·열기 | 링크는 "열기"로 원본(YouTube 앱 등)을 연다. 사진은 크게 보기·좌우 넘기기 | 필수 |
| F11 | 수정·삭제 | 카테고리·키워드·제목·메모 수정. 삭제 후 5초간 "되돌리기" | 필수 |
| F12 | 백업·복원 | 전체를 파일 하나로 내보내고(공유 시트 → 파일에 저장), 다시 가져온다. 마지막 백업 후 30일이 지나면 알림 | 필수 |
| F13 | 공유 시트에서 보내기 | iOS 단축어 앱으로 "저장소에 담기" 단축어를 만들어, YouTube·Safari 공유 버튼에서 앱의 추가 화면을 링크가 채워진 채로 연다 | 권장 |
| F14 | 중복 링크 알림 | 이미 저장한 URL이면 "이미 레시피에 있어요"로 알려주고 그 항목으로 이동 | 권장 |
| F15 | 상단 고정(핀) | 자주 보는 항목을 카테고리 맨 위에 고정 | 권장 |
| F16 | 미리보기 다시 불러오기 | 실패했거나 바뀐 링크의 제목·썸네일을 다시 가져오기 | 권장 |
| F17 | 정렬·보기 전환 | 최신순/오래된순, 목록/카드/격자 전환 | 나중 |
| F18 | 클라우드 동기화 | PC에서도 보기, 폰 바꿔도 유지 | 나중 |

## 화면 구성과 사용 흐름

화면은 5개다. 홈과 카테고리 화면에서 거의 모든 일을 하고, 추가는 아래에서 올라오는 시트로 처리한다.

- **홈**: 검색창, 카테고리 타일 6개, 최근 저장 목록, 오른쪽 아래 + 버튼. 오른쪽 위에 설정 아이콘.
- **카테고리 화면**: 제목(누르면 카테고리 전환 메뉴), 그 카테고리 안 검색, 항목 목록, 오른쪽 아래 + 버튼. 여기서 누른 +는 그 카테고리가 미리 선택된다.
- **추가 시트**: 링크 / 사진 / 텍스트를 고르면 입력 칸이 바뀐다. 아래쪽에 카테고리 버튼 6개와 키워드 칸이 공통으로 붙는다.
- **상세**: 큰 미리보기, 제목, 키워드 칩, 메모, "열기" 버튼, 수정·삭제·고정.
- **설정**: 백업 내보내기·가져오기, 마지막 백업 날짜, 사용 중인 저장 공간.

항목 추가 흐름 (어떤 경로로 넣든 카테고리와 키워드를 거쳐 저장된다):

```
[공유 시트 → 단축어] (권장, 링크가 채워진 채로) ─┐
[메인 화면 + 버튼] ─┬─ 링크 붙여넣기 ─────── 제목·썸네일 자동 생성 (실패하면 직접 입력) ─┐
                    ├─ 사진 선택·촬영 ─────── 축소 + 썸네일 생성 (1600px 원본 · 400px 썸네일) ─┤
                    └─ 텍스트 입력 (제목(선택) + 본문) ─────────────────────────────────────┤
                                                                                         ▼
                              카테고리 선택 + 키워드 입력 (링크·사진은 키워드 권장, 자동완성)
                                                                                         ▼
                                              저장 → 지금 탭 맨 위에 표시
```

입력 경로는 달라도 마지막은 항상 카테고리와 키워드 단계를 거친다. 공유 시트 경로는 실기기 확인 후 붙이는 권장 기능이다.

## 기술적 제약과 해결 방안

가장 큰 제약은 두 가지다. 웹앱은 다른 사이트의 제목·썸네일을 직접 읽지 못하고, 아이폰 공유 시트에 나타나지 못한다. 둘 다 우회로가 있다.

| 제약 | 내용 | 해결 방안 |
| --- | --- | --- |
| 링크 미리보기 (CORS) | 브라우저는 상대 사이트가 허락하지 않으면 그 페이지 HTML을 읽지 못한다 ([MDN](https://developer.mozilla.org/en-us/docs/web/http/access_control_cors)) | Cloudflare Worker 함수가 대신 페이지를 읽고 `og:title`, `og:image`, `og:site_name`, `<title>`을 뽑아 돌려준다. 대표 이미지도 이 함수를 거쳐 받아 폰에 저장한다 |
| YouTube 영상 | 제목·채널·썸네일을 주는 공식 oEmbed 주소가 있다 ([참고](https://community.spotify.com/t5/Spotify-for-Developers/OEmbed-API-missing-CORS-headers/m-p/5264013)) | `youtube.com/oembed`로 제목·채널을 받고, 썸네일은 영상 ID로 바로 만든다. Shorts 링크도 같은 방식 |
| 로그인이 필요한 사이트 | 인스타그램 등은 외부에서 읽으면 제목·이미지가 안 나올 수 있다 | 실패하면 도메인을 제목으로 두고, 제목 직접 입력 + 스크린샷을 미리보기로 지정할 수 있게 한다. 키워드가 더 중요해지는 경우 |
| 공유 시트 | iOS Safari는 웹앱이 공유 대상이 되는 Web Share Target을 지원하지 않는다 ([WebKit 버그 194593](https://bugs.webkit.org/show_bug.cgi?id=194593)) | 단축어 앱: 공유 시트에서 URL을 받아 `앱주소/?add=<링크>`를 여는 단축어를 만든다. 단, 홈 화면 앱이 아니라 Safari 탭으로 열릴 수 있어 실기기 확인이 필요하다(아래 저장소 분리 참고). 안 되면 클립보드 복사 → 앱에서 붙여넣기로 대신한다 |
| 7일 데이터 삭제 | Safari에서 연 사이트는 일정 기간 안 쓰면 저장 데이터가 지워질 수 있다. 홈 화면 웹앱은 Safari와 별도로 계산된다 ([OSnews](https://www.osnews.com/story/131566/apple-just-killed-offline-web-apps-while-purporting-to-protect-your-privacy/)) | 반드시 홈 화면 아이콘으로만 쓴다. 첫 실행 때 `navigator.storage.persist()`로 영구 저장을 요청한다 |
| 저장 공간 | iOS 17부터 한 사이트당 디스크의 최대 60%까지 쓸 수 있고 홈 화면 웹앱도 같다. 다만 저장 공간이 부족하면 오래 안 쓴 사이트부터 지워질 수 있다 ([WebKit](https://webkit.org/?p=14403)) | 영구 저장 요청 + 정기 백업(F12). 설정 화면에 사용량 표시(`navigator.storage.estimate()`) |
| 저장소 분리 | 홈 화면 앱과 Safari 탭은 데이터를 따로 갖는다(실기기에서 확인 필요) | 모든 저장은 홈 화면 앱에서. Safari 탭에서 열리면 "홈 화면 앱에서 열어 주세요" 안내 |
| 사진 용량 | 아이폰 원본 사진은 장당 수 MB다 | 긴 변 1600px JPEG(약 0.3MB)로 줄이고 목록용 400px 썸네일(약 30KB)을 따로 둔다. 사진 1,000장에 약 330MB 예상 |
| 미리보기 함수 남용 | 주소가 알려지면 다른 사람도 쓸 수 있다 | 내 앱 주소에서 온 요청만 받고, 간단한 비밀 키를 붙인다 |

사진 용량 수치는 예상치다. 개발 후 실제 사진으로 다시 잰다.

### 자주 쓰는 사이트별 미리보기 전망

4개 사이트 중 YouTube만 확실히 된다. 인스타그램과 쿠팡은 실패를 전제로 설계하고, 네이버 블로그는 개발 때 실제로 확인한다.

| 사이트 | 예상 | 방안 |
| --- | --- | --- |
| YouTube | 됨 | 공식 oEmbed로 제목·채널, 영상 ID로 썸네일. Shorts 포함 |
| 네이버 블로그 | 확인 필요 | PC용 주소(`blog.naver.com`)는 본문이 페이지 안 프레임에 들어 있다. 모바일 주소(`m.blog.naver.com`)로 바꿔 읽는 방식을 시험한다 |
| 인스타그램 | 자주 실패 | 텔레그램·Discourse 같은 서비스도 서버에서 인스타그램 미리보기를 못 만드는 사례가 있다 ([텔레그램](https://bugs.telegram.org/c/59998), [Discourse](https://meta.discourse.org/t/missing-preview-for-artstation-links/276417?tl=en)). 실패하면 스크린샷을 미리보기로 지정하고 키워드 입력을 권한다 |
| 쿠팡 | 실패 예상 | 쿠팡은 브라우저가 아닌 요청에 403 접근 거부를 돌려준다 ([사례](https://www.digitalmarketer.co.kr/insights/coupang-robots-txt-partners-strategy)). 쿠팡 앱의 공유 문구에 상품명이 함께 오면 그 줄을 제목으로 쓰고, 아니면 스크린샷을 미리보기로 쓴다 |

그래서 링크 추가 칸에 붙여넣은 글에 URL 외의 문구가 있으면 그것을 제목 후보로 쓰고, 미리보기가 없을 때 "스크린샷 고르기" 버튼을 보여준다(F2).

## 개발 단계와 열린 질문

4단계로 나눠 만든다. 각 단계가 끝날 때마다 아이폰에서 직접 써 보고 다음으로 넘어간다.

1. **뼈대 — 텍스트·탭·저장**: 홈·카테고리 화면, 텍스트 추가(F4), 카테고리(F5), 키워드(F6), 목록(F7), 수정·삭제(F11), IndexedDB 저장, 홈 화면 추가. GitHub Pages에 올려 아이폰에서 확인.
2. **사진**: 사진 추가·축소·썸네일(F3), 짤방 격자 보기, 사진 크게 보기(F10).
3. **링크와 미리보기**: Cloudflare Worker 함수 만들기, 링크 추가(F1), 미리보기(F2), YouTube 전용 처리, 실패 시 직접 입력.
4. **찾기와 지키기**: 검색(F8), 키워드 필터(F9), 백업·복원(F12), 영구 저장 요청. 여기까지가 1차 완성.

이후 쓰면서 권장 항목(F13~F16)을 하나씩 붙인다. 단축어 연동(F13)은 저장소 분리 문제 때문에 실기기 실험이 먼저다.
