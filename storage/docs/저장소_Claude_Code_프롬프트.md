# 저장소 웹앱 — Claude Code 프롬프트 모음

`저장소_기획문서.md`를 바탕으로, VS Code의 Claude Code에 단계별로 붙여넣을 프롬프트입니다.

## 쓰는 법

- GitHub 리포지토리: https://github.com/Leehagyeol/Repository (현재 비어 있음)
- PC 폴더: `C:\Users\문하해\Documents\Claude\Repository` (이 파일과 기획문서가 들어 있는 폴더)
- 앱 주소(완성 후): `https://leehagyeol.github.io/Repository/storage/`

1. VS Code에서 **위 PC 폴더**를 엽니다(파일 → 폴더 열기).
2. 아래 프롬프트를 **0단계부터 순서대로** 하나씩 Claude Code에 붙여넣습니다. 0단계에서 이 폴더를 GitHub 리포지토리와 연결하고 기획문서를 `storage/docs/`로 옮깁니다.
3. 각 단계가 끝나면 Claude Code에 "커밋하고 푸시해줘"라고 한 뒤, 1~2분 기다렸다가 아이폰 홈 화면 앱으로 "확인할 것"을 직접 해 봅니다. 문제가 없을 때 다음 단계로 넘어갑니다.
4. 문제가 있으면 그 단계에서 "○○가 안 돼. 아이폰에서 이렇게 보여: …"처럼 증상을 그대로 알려 주면 됩니다.

> 앱은 리포지토리 안 `storage/` 폴더에 만듭니다. 나중에 같은 리포지토리에 다른 앱을 넣어도 섞이지 않게 하기 위해서입니다.

## 0단계 — 준비와 계획 (앱 코드 작성 없음)

```
이 폴더에 있는 저장소_기획문서.md 를 끝까지 읽어줘. 이 문서대로 아이폰 Safari 홈 화면용 웹앱 "저장소"를 만들 거야.

- GitHub 리포지토리: https://github.com/Leehagyeol/Repository (지금은 비어 있음)
- 이 PC 폴더는 아직 Git에 연결되어 있지 않아.
- 앱은 리포지토리 안 storage/ 폴더에 만들고, GitHub Pages 주소는 https://leehagyeol.github.io/Repository/storage/ 가 될 거야.
- 장보기 앱은 같은 GitHub 계정(leehagyeol.github.io)의 다른 리포지토리에 있어. 리포지토리는 달라도 브라우저는 같은 사이트로 보니까 서로 간섭하지 않게 해야 해.

이번에는 앱 코드를 쓰지 말고 아래만 해줘.
1. Git 준비: Git이 설치되어 있는지 확인하고, 이 폴더를 위 GitHub 리포지토리와 연결해줘(git init, 기본 브랜치 main, remote 추가). 로그인이 필요하면 내가 할 일을 알려줘.
2. 파일 정리: 저장소_기획문서.md 와 저장소_Claude_Code_프롬프트.md 를 storage/docs/ 로 옮기고, 리포지토리 루트에 짧은 README.md 와 .gitignore 를 만들어줘.
3. 기획문서의 "개발 단계" 4단계에 맞춘 storage/ 폴더 구조와 파일 목록을 제안해줘.
4. 장보기 앱과 데이터·서비스 워커·홈 화면 아이콘에서 서로 간섭하지 않도록 어떻게 나눌지 적어줘.
5. 아래 "공통 규칙"을 storage/CLAUDE.md 파일로 저장해줘. 앞으로 모든 단계에서 이 규칙을 지켜.
6. 첫 커밋을 만들고 푸시해줘. 그다음 GitHub Pages를 켜는 방법(Settings → Pages → Deploy from a branch → main / root)을 단계별로 알려줘. 이건 내가 GitHub 웹사이트에서 직접 할게.

[공통 규칙]
- 기획문서(storage/docs/저장소_기획문서.md)가 기준이다. 문서와 다르게 해야 할 이유가 생기면 먼저 나에게 묻는다.
- HTML + CSS + JavaScript만 쓴다. 빌드 도구, 프레임워크, npm 패키지는 쓰지 않는다. 외부 라이브러리가 꼭 필요하면 먼저 묻는다.
- 앱 파일은 모두 storage/ 폴더 안에 둔다. 리포지토리 루트에는 README.md, .gitignore 외에 파일을 늘리지 않는다.
- 커밋·푸시는 내가 요청할 때만 한다.
- 데이터는 IndexedDB에 저장하고, DB 이름은 "storage-db", localStorage 키는 "storage-"로 시작한다.
- 서비스 워커는 storage/ 안에 두고 scope를 storage/로 제한한다. manifest의 start_url과 scope도 storage/로 한다.
- 아이폰 Safari(iOS 17 이상) 홈 화면 앱 기준으로 만든다. 터치 영역은 최소 44×44pt, 아래쪽 안전 영역(safe-area-inset)을 지킨다.
- 색: 대표색 #2F6F68(짙은 청록), 바탕 #F6F1E7(미색), 강조 #E9B44C(노랑, 글자에는 쓰지 않음), 다크 모드 배경 #1C2321. 다크 모드는 아이폰 설정을 따른다.
- 카테고리 목록(레시피, 육아, 만들기, 쇼핑, 메모, 짤방)은 설정 파일 한 곳에 모아 둔다.
- 화면에 보이는 글자는 모두 한국어로 쓴다.
- 각 단계가 끝나면 (1) 바꾼 파일 목록, (2) 아이폰에서 확인할 것, (3) 다음 단계 전에 내가 할 일을 짧게 정리해준다.
```

## 1단계 — 뼈대: 홈·카테고리·텍스트·저장

```
storage/CLAUDE.md 규칙과 기획문서를 기준으로 1단계를 만들어줘.

만들 것:
- 홈 화면(C안): 위에서부터 앱 제목 "저장소"와 오른쪽 위 설정 아이콘, 검색창(이번 단계에서는 자리만), 카테고리 타일 6개(2열×3줄, 타일마다 이름과 항목 수), "최근 저장" 목록, 오른쪽 아래 + 버튼.
- 카테고리 화면: 제목 "레시피 ▾"를 누르면 카테고리 전환 메뉴가 펼쳐진다. 왼쪽 위 ‹ 버튼으로 홈에 돌아간다. 항목 목록과 + 버튼.
- 추가 시트(아래에서 올라옴): 이번 단계에서는 "텍스트"만. 제목(선택), 본문, 카테고리 버튼 6개, 키워드 입력(F4, F5, F6).
  - 카테고리 기본값은 지금 보고 있던 카테고리, 홈에서 열면 직접 선택.
  - 키워드는 엔터·쉼표·띄어쓰기로 칩이 되고, 전에 쓴 키워드를 자동완성으로 추천한다.
- 목록(F7): 최신순. 텍스트 항목은 제목 + 본문 앞 2줄.
- 상세 화면과 수정·삭제(F11). 삭제 후 5초간 "되돌리기".
- 기획문서 "항목 유형과 데이터 모델"의 필드 구조로 IndexedDB에 저장. 사진·링크 필드도 미리 자리를 만들어 둔다.
- 앱을 다시 열면 마지막에 보던 화면(홈 또는 그 카테고리)에서 시작.
- 홈 화면 앱 설정: manifest.json, 서비스 워커(오프라인에서도 열리게), apple-touch-icon 등 iOS용 meta 태그.
- 아이콘: 기획문서의 "이름·아이콘·색" 표대로 서랍 아이콘을 SVG로 그리고, 180×180, 192×192, 512×512 PNG를 만들어줘. PNG를 직접 만들 수 없으면 SVG와, PNG로 바꾸는 가장 쉬운 방법을 알려줘.
- Safari 탭에서 열렸을 때(홈 화면 앱이 아닐 때)는 위쪽에 "공유 버튼 → 홈 화면에 추가 후 그 아이콘으로 열어 주세요" 안내를 띄워줘.

다 만들면 PC 브라우저에서 확인하는 방법과, 푸시한 뒤 아이폰 Safari에서 https://leehagyeol.github.io/Repository/storage/ 를 열어 홈 화면에 추가하는 순서를 알려줘.
```

**아이폰에서 확인할 것**
- 홈 화면에 추가했을 때 서랍 아이콘과 "저장소" 이름이 보이는지
- 장보기 앱 아이콘을 눌렀을 때 장보기 앱이 그대로 잘 열리는지
- 텍스트를 저장하고 앱을 완전히 닫았다가 다시 열어도 남아 있는지
- 카테고리 제목 메뉴로 다른 카테고리로 바로 옮겨지는지
- 비행기 모드에서도 앱이 열리는지

## 2단계 — 사진

```
storage/CLAUDE.md 규칙과 기획문서를 기준으로 2단계를 만들어줘. 1단계 기능은 그대로 유지해.

만들 것:
- 추가 시트에 "사진" 유형 추가(F3): 사진 보관함에서 여러 장 선택, 또는 카메라 촬영.
  - 저장할 때 긴 변 1600px JPEG(품질 약 0.8)로 줄이고, 목록용 400px 썸네일을 따로 만든다.
  - 아이폰 HEIC 사진도 문제없이 들어가게 해줘.
  - 제목·메모는 선택, 키워드가 비어 있으면 "키워드를 넣으면 찾기 쉽습니다" 안내(저장은 막지 않음).
- 목록 모양: 짤방은 사진 격자(3열), 레시피·만들기는 카드(썸네일 크게), 나머지는 목록. 이 설정도 카테고리 설정 파일에 넣어줘.
- 상세 화면에서 사진 크게 보기, 여러 장이면 좌우로 넘기기(F10).
- 설정 화면을 만들고 "사용 중인 저장 공간"을 navigator.storage.estimate()로 보여줘.

사진 몇 장을 넣었을 때 실제로 저장 공간이 얼마나 늘었는지 확인하는 방법도 알려줘.
```

**아이폰에서 확인할 것**
- 사진 10장을 한 번에 넣어도 멈추지 않는지
- 짤방 격자, 레시피 카드가 보기 좋은지
- 사진을 넣은 뒤 설정 화면의 사용량이 늘었는지 (사진 1장에 약 0.3MB 예상)

## 3단계 — 링크와 미리보기

이 단계에는 **Cloudflare 계정**이 필요합니다(무료). 가입과 로그인은 직접 해 주세요. Claude Code는 함수 코드와 배포 방법을 준비합니다.

```
storage/CLAUDE.md 규칙과 기획문서를 기준으로 3단계를 만들어줘. 기획문서의 "기술적 제약과 해결 방안"과 "자주 쓰는 사이트별 미리보기 전망"을 꼭 다시 읽어.

1) 미리보기 함수 (Cloudflare Worker)
- storage/worker/ 폴더에 Cloudflare Worker 코드를 만들어줘. 이 폴더는 GitHub Pages에 올라가도 상관없지만 비밀 키는 코드에 넣지 마.
- 요청: ?url=<링크>. 응답: JSON { title, siteName, description, image(이미지 주소), ok }.
- 페이지 HTML에서 og:title, og:site_name, og:description, og:image, <title> 순서로 뽑는다.
- 대표 이미지를 앱이 폰에 저장할 수 있게 ?image=<이미지주소> 로 이미지를 대신 받아 주는 기능도 넣어줘.
- https://leehagyeol.github.io 에서 온 요청만 허용하고(CORS), 간단한 비밀 키 헤더를 확인해줘.
- 사이트별 처리:
  - YouTube(일반, Shorts, youtu.be): oEmbed로 제목·채널, 썸네일은 영상 ID로 만든다.
  - 네이버 블로그: blog.naver.com 주소는 m.blog.naver.com 주소로 바꿔서 읽는다.
  - 인스타그램·쿠팡: 실패할 가능성이 높다. 실패하면 ok:false로 빨리 돌려준다(5초 안에).
- Windows에서 이 함수를 배포하는 순서를 처음 하는 사람 기준으로 단계별로 적어줘(wrangler 설치, 로그인, 비밀 키 설정, 배포, 주소 확인). 명령어는 내가 직접 실행할게.

2) 앱 쪽
- 추가 시트에 "링크" 유형 추가(F1). 클립보드에 링크가 있으면 "붙여넣기" 버튼을 먼저 보여준다.
- 붙여넣은 글에 URL 말고 다른 문구가 있으면(예: 쿠팡 앱 공유 문구의 상품명) 그것을 제목 후보로 쓴다.
- 링크를 넣으면 미리보기 함수를 불러 제목·썸네일을 입력 화면에 바로 보여준다(F2). 대표 이미지는 폰에 사본으로 저장.
- 실패하면 도메인 이름을 제목으로 두고, 제목을 직접 고칠 수 있게 하고, "스크린샷 고르기" 버튼으로 사진을 미리보기 이미지로 지정할 수 있게 해줘.
- 목록 모양: 영상은 썸네일 + ▶ 표시 + 제목, 웹페이지는 대표 이미지 + 제목 + 도메인.
- 상세 화면의 "열기"는 원본 링크를 연다(YouTube는 YouTube 앱으로 열리면 좋음).
- 미리보기 함수 주소와 비밀 키는 설정 화면에서 입력해 localStorage에 저장하게 해줘(코드에 넣지 않음).
```

**아이폰에서 확인할 것**
- YouTube 영상, YouTube Shorts, 네이버 블로그, 인스타그램, 쿠팡 링크를 하나씩 넣어 보고 각각 어떻게 나오는지
- 인스타그램·쿠팡에서 실패했을 때 스크린샷으로 미리보기를 지정할 수 있는지
- 네이버 블로그가 안 되면 그 결과를 Claude Code에 그대로 알려 주기

## 4단계 — 찾기와 지키기 (1차 완성)

```
storage/CLAUDE.md 규칙과 기획문서를 기준으로 4단계를 만들어줘.

만들 것:
- 검색(F8): 제목·키워드·메모·사이트 이름에서 찾는다. 홈에서는 전체, 카테고리 화면에서는 그 카테고리 안에서. 한글 부분 일치로 찾아줘.
- 키워드 필터(F9): 항목의 키워드 칩을 누르면 같은 키워드가 붙은 항목만 보인다. 필터 해제 버튼도.
- 백업·복원(F12): 설정 화면에서
  - "백업 내보내기": 사진과 미리보기 이미지를 포함해 파일 하나로 만들고 아이폰 공유 시트로 넘겨서 "파일에 저장"할 수 있게.
  - "백업 가져오기": 그 파일을 골라 복원. 기존 데이터와 겹치면 어떻게 할지(덮어쓰기/합치기) 물어본다.
  - 마지막 백업 날짜를 보여주고, 30일이 지나면 홈에 백업 알림을 띄운다.
- 첫 실행 때 navigator.storage.persist()로 영구 저장을 요청하고, 결과를 설정 화면에 보여준다.
- 전체 기능을 기획문서의 F1~F12와 하나씩 대조해서 빠진 것이 있는지 점검표로 보여줘.
```

**아이폰에서 확인할 것**
- 키워드 하나로 검색했을 때 여러 카테고리의 항목이 다 나오는지
- 백업 파일을 iCloud Drive에 저장 → 앱 데이터를 지우고 → 복원했을 때 사진까지 돌아오는지
- 설정 화면에 "영구 저장: 허용됨"이 보이는지

**F13 공유 시트에서 보내기 (먼저 실험)**
```
기획문서의 F13과 "공유 시트", "저장소 분리" 항목을 읽어줘. 앱이 ?add=<링크> 주소로 열리면 링크 추가 시트를 링크가 채워진 채로 여는 기능을 만들어줘. 그리고 아이폰 단축어 앱에서 "저장소에 담기" 단축어를 만드는 방법을 단계별로 알려줘(공유 시트에서 URL 받기 → 앱 주소 열기). 이 방법이 홈 화면 앱이 아니라 Safari 탭으로 열리면 데이터가 따로 저장될 수 있으니, 그 경우 Safari 탭에서는 저장하지 말고 "링크를 복사했어요, 홈 화면 앱에서 붙여넣어 주세요"로 안내하는 대안도 함께 만들어줘.
```

**F14 중복 링크 알림**
```
기획문서 F14를 만들어줘. 이미 저장한 URL을 다시 넣으면 "이미 ○○에 있어요"로 알려주고 그 항목으로 이동할 수 있게. YouTube는 youtu.be, 일반 주소, Shorts가 같은 영상이면 같은 링크로 판단해줘.
```
